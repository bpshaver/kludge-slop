# Process improvement notes

Friction with the coordination workflow itself (this README, ROLES.md, the
phase/claim/liveness mechanics) — not feature content. See the "process_improvement.md"
section of README.md for what belongs here.

**Mark entries as resolved rather than deleting them.** A resolved entry is the
record of why a rule has the shape it does; delete it and the next person to find
that rule awkward has no idea what it cost to learn. Two habits keep this file
honest as it ages:

- When an entry gets folded into `README.md`/`ROLES.md`, add a dated resolution
  note saying what it turned into — as its own entry at the end, and a one-line
  marker on the entry itself.
- An unmarked stale entry reads as an open problem and gets solved a second time.
  If most of the file is resolved, say so near the top so a fresh reader isn't
  working from a list of things that were fixed weeks ago.
